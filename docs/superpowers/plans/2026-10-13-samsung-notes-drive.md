# Samsung Notes → Google Drive (pasta vigiada, celular e tablet) — Design e Plano

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:test-driven-development. Regras comuns do plano `2026-10-12-series-alarmes-github-drive.md` valem aqui (pt-BR, banco só local, sem commit, sem nuvem/VM, arquivos compartilhados com edição pequena e ancorada).

**Aprovado no chat (2026-10-13).** Não existe API do Samsung Cloud nem sync com OneNote (encerrado em jul/2026). Fluxo: no Samsung Notes o usuário usa "Salvar como arquivo" (PDF/Word/texto/imagem); o Organizacional **acha sozinho** a pasta onde esses arquivos caem, e **sincroniza automaticamente** com o Google Drive (`Organizacional/Samsung Notes`), criando uma nota-link para cada arquivo — em qualquer aparelho (celular e tablet rodam o mesmo APK). Botão "Abrir Samsung Notes" abre o app da Samsung (não há como abrir uma nota específica).

## Contrato entre as tasks (fixo)

**Banco `20261022000000_imported_files.sql`:** `imported_files(user_id uuid not null default auth.uid() references auth.users on delete cascade, sha256 text not null check (sha256 ~ '^[0-9a-f]{64}$'), name text not null, size_bytes bigint not null check (size_bytes >= 0), source text not null default 'samsung_notes' check (source in ('samsung_notes','import','share')), drive_file_id text, note_id uuid references notes(id) on delete set null, device text, created_at timestamptz not null default now(), primary key (user_id, sha256))` + RLS do dono (select/insert/update; sem delete pelo cliente) + realtime. O **sha256 do conteúdo** é a chave de deduplicação entre aparelhos: o mesmo arquivo exportado no celular e no tablet só sobe uma vez.

**Função `drive` (ação nova, mesma autenticação):** `ensure_path {path: ["Organizacional","Samsung Notes"]}` → `{folderId}` (acha/cria cada nível a partir do Meu Drive; nomes validados, sem `/`). O `upload_session` existente passa a aceitar opcional `appProperties: {sha256: "<64 hex>"}` (validado) e grava no arquivo do Drive; nova ação `find_by_sha256 {sha256}` → `{file: {id, name, webViewLink} | null}` (query `appProperties has { key='sha256' and value='…' } and trashed=false`).

## Task A — servidor (migração + função drive)

Arquivos: a migração + `supabase/tests/database/imported_files_test.sql` (RLS: outro usuário não lê/escreve; checks; PK impede duplicata), `supabase/functions/drive/handler.ts` e `handler_test.ts`, `_shared/drive.ts` se precisar. Testes Deno com fetch falso: `ensure_path` cria o que falta e reaproveita o que existe; nome inválido → 400; `find_by_sha256` com/sem resultado; `appProperties` inválido → 400; o `upload_session` sem `appProperties` continua igual (compatível). Rodar `deno test -A` (tudo verde, inclusive Gmail/Drive) e `npx supabase migration up --local` + `npx supabase test db`. Não toque em `app/`.

## Task B — app (Android + Linux)

1. **Achar a pasta (Android):** pedir "Acesso a todos os arquivos" (`MANAGE_EXTERNAL_STORAGE`, Android 11+; o app é pessoal, fora da Play Store) com explicação antes; depois procurar, nesta ordem, pastas existentes: `Documents/Samsung Notes`, `Download/Samsung Notes`, `Samsung Notes`, `Documents/Samsung`, `Download` (só arquivos cujo nome/metadado indique Samsung Notes não é confiável — então em `Download` só se o usuário confirmar), e por fim uma busca por diretório chamado `Samsung Notes` até profundidade 3 sob `/storage/emulated/0`. Mostrar o que achou e deixar trocar com um seletor de pasta (SAF `OpenDocumentTree`) — se o usuário escolher via SAF, usar o URI persistido em vez do caminho. Linux: escolher a pasta com `file_picker` (`getDirectoryPath`).
2. **Sincronização (`lib/features/samsung_notes/` ou `lib/import/folder_sync.dart`):** listar arquivos `.pdf .docx .doc .txt .md .png .jpg .jpeg .sdocx`? — **não** `.sdocx` (formato fechado; ignore e conte como "ignorados"). Para cada arquivo: sha256 (streaming) → se já existe linha em `imported_files` (do usuário) **ou** `find_by_sha256` acha no Drive → pula (e grava a linha se faltava); senão `ensure_path` (cache do folderId), `upload_session` com `appProperties.sha256` + PUT, cria a nota-link (mesmo formato da nota-link da folha de compartilhar já existente; espaço "Samsung Notes", criado se faltar; `.txt/.md` ≤ 1 MB viram nota com o texto **e** sobem ao Drive), grava `imported_files`. Arquivo alterado (mesmo nome, outro sha) = novo arquivo (versão nova, título com a data). Nunca apaga nada no Drive nem no aparelho.
3. **Quando roda:** ao abrir/retomar o app (foreground) e em segundo plano com `workmanager` (tarefa `samsung-notes-sync`, a cada 15 min, só com rede, reaproveitando a infra do `location_background`/widgets e a sessão Supabase salva), só se a sincronização estiver ligada e o Drive conectado. Sem sessão/Drive → não faz nada. Uma execução por vez (trava simples).
4. **UI:** Ajustes → "Samsung Notes" (`Key('samsung-notes-card')`): status (pasta encontrada, último sync "há 5 min", "12 enviados, 2 ignorados"), botões "Procurar pasta", "Escolher outra pasta", chave "Sincronizar automaticamente" (`Key('samsung-sync-toggle')`), "Sincronizar agora", ajuda curta ("No Samsung Notes: abra a nota → ⋮ → Salvar como arquivo → PDF"). Sem Drive conectado → aviso com atalho para conectar. Em Notas, ação "Abrir Samsung Notes" (`Key('open-samsung-notes')`, só Android e só se o pacote `com.samsung.android.app.notes` estiver instalado) e nas notas-link vindas do Samsung Notes os botões "Abrir no Drive" e "Abrir Samsung Notes".
5. **Kotlin:** canal `dev.organizacional/samsung_notes`: `isInstalled()`, `open()` (launch intent do pacote), `hasAllFilesAccess()`, `requestAllFilesAccess()` (abre `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`), `findFolders()` (as buscas do item 1, devolvendo caminhos), `pickFolder()` (SAF, persiste permissão) e leitura por SAF quando o caminho for um URI. Manifesto: `MANAGE_EXTERNAL_STORAGE` (+ `READ_EXTERNAL_STORAGE` maxSdk 32) e `<queries><package android:name="com.samsung.android.app.notes"/></queries>`.
6. **Testes:** motor de sync com fakes (FS, Drive repo, imported_files repo): novo arquivo sobe e cria nota; mesmo sha já registrado → pula; existe só no Drive → pula e registra; `.sdocx` ignorado; erro no upload não grava registro e tenta de novo depois; trava impede execução dupla; texto ≤1 MB vira nota com conteúdo. Telas: cartão de Ajustes (estados), botão em Notas só quando instalado. JUnit para a lógica pura de busca de pastas (ordem e profundidade, com diretório temporário). `flutter analyze` limpo, suíte verde, `./gradlew :app:testDebugUnitTest`, `flutter build apk --debug` e conferir no manifesto mesclado a permissão e o `<queries>`.
