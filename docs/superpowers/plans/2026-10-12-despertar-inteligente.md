# Despertar inteligente (clima, casa de 50 m, dispositivos; depois alarme no celular) — Design e Plano

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development ou executing-plans. Steps com checkbox.

**Aprovado no chat (2026-10-12).** Decisões do usuário: (1) sem localização recente na hora do despertar → **toca mesmo assim** (só pula quando tem certeza de que está fora); (2) fora de casa as luzes **só não ligam** (nunca são apagadas pela ponte).

## Comportamento (Fase 1)

**Clima.** Em cada despertar (`include_weather`, padrão `true`) a ponte busca a previsão no **Open-Meteo** (`https://api.open-meteo.com/v1/forecast?latitude=..&longitude=..&current=temperature_2m,weather_code&daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max&timezone=America%2FSao_Paulo&forecast_days=1`, sem chave) e fala logo depois do cumprimento/data: "Em Belo Horizonte agora faz 22 graus, céu parcialmente nublado. Hoje a máxima é de 28 e a mínima de 17, com 40% de chance de chuva." O local é a **última localização do celular** (se tiver até 3 h), senão a **casa**, senão não fala clima. Nome da cidade: reverse geocoding no **Nominatim** (`https://nominatim.openstreetmap.org/reverse?lat=..&lon=..&format=jsonv2&zoom=10&accept-language=pt-BR`, com `User-Agent: organizacional-bridge/1.0`, cache em memória por coordenada arredondada a 2 casas, no máx. 1 requisição/dia); falhou → fala sem o nome da cidade ("Agora faz 22 graus…"). Timeout de 5 s por chamada; qualquer falha → sem clima, o resto do despertar segue. Códigos WMO → pt-BR (0 "céu limpo", 1 "predominantemente limpo", 2 "parcialmente nublado", 3 "nublado", 45/48 "neblina", 51–57 "garoa", 61–67 "chuva", 71–77 "neve", 80–82 "pancadas de chuva", 85–86 "pancadas de neve", 95–99 "trovoadas").

**Minha casa e presença.** `user_settings`: `home_lat`, `home_lon`, `home_radius_m` (padrão 50), `require_home` (padrão `true`; só vale se a casa estiver definida). O celular reporta `user_locations` (lat, lon, accuracy_m, reported_at). Na hora do despertar a ponte avalia: sem casa ou `require_home=false` → **toca**; sem localização ou com mais de **45 min** → **toca** (desconhecido); senão `d = haversine(casa, celular)` e fica "em casa" se `d − min(accuracy, 25) ≤ raio` (a margem cobre o erro do GPS dentro de casa), caso contrário "fora". **Fora:** o despertar **não toca** (nem música, nem fala, nem lâmpadas), o **alarme reserva do Echo é apagado** e a execução termina com status `skipped` e a nota "fora de casa (a X m)". "Testar agora" **ignora** a presença.

**Dispositivos na rotina.** `wake_plans.device_actions` (jsonb array): `{ "entityId": str, "name": str, "action": "turnOn"|"turnOff"|"setBrightness", "brightness"?: 0–100, "delayMin": 0–30 }`. Ao disparar (e presente), a ponte executa cada ação após seu atraso, **em paralelo** com a música e a fala (não as atrasa); falha de uma ação vira nota e não impede as outras; ao final espera as pendentes. Só dispositivos `kind='smart'`.

**`phone_alarm`** (`'never'|'fallback'|'always'`, padrão `'fallback'`) é criado já na migração desta fase mas só é usado na **Fase 2**.

## Dados (migração `supabase/migrations/20261013000000_smart_wake.sql`, depois da `20261012000000_wake_music_stop.sql`)

- `user_locations(user_id uuid primary key default auth.uid() references auth.users on delete cascade, lat double precision not null check (lat between -90 and 90), lon double precision not null check (lon between -180 and 180), accuracy_m real check (accuracy_m >= 0), reported_at timestamptz not null default now())` + RLS do dono.
- `user_settings` += `home_lat double precision`, `home_lon double precision`, `home_radius_m integer not null default 50 check (home_radius_m between 20 and 500)`, `require_home boolean not null default true`, `check ((home_lat is null) = (home_lon is null))` e checks de faixa.
- `wake_plans` += `include_weather boolean not null default true`, `device_actions jsonb not null default '[]' check (jsonb_typeof(device_actions) = 'array')`, `phone_alarm text not null default 'fallback' check (phone_alarm in ('never','fallback','always'))`.
- `wake_runs.status` aceita `'skipped'` (recriar o check).
- pgTAP: RLS de `user_locations` (outro usuário não lê/escreve), todos os checks (válidos passam, inválidos falham), `skipped` aceito.

## Tasks

### Task A — Ponte: módulos puros (`weather.ts`, `presence.ts`) — pode começar já
Files: `bridge/src/weather.ts`, `bridge/src/presence.ts`, `bridge/test/weather.test.ts`, `bridge/test/presence.test.ts`. **Não** altere `wake.ts`, `scheduler.ts`, `supabase-store.ts`, `main.ts`, `gateway.ts` (outro agente está nelas).
- `presence.ts`: `haversineM(a, b)`, `evaluatePresence({ home: {lat,lon,radiusM}|null, requireHome: boolean, location: {lat,lon,accuracyM:number|null,reportedAt:Date}|null, now: Date, maxAgeMin?: number /*45*/ }): { state: 'not_required'|'home'|'away'|'unknown', distanceM: number|null }` com a regra do spec (margem `min(accuracy, 25)`). Testes: sem casa; `require_home=false`; sem localização; localização de 46 min → `unknown`; a 10 m → `home`; a 70 m com precisão 30 → `home` (70−25=45); a 80 m com precisão 30 → `away`; Belo Horizonte vs. São Paulo → `away`; coordenadas idênticas → 0 m.
- `weather.ts`: `fetchWeather(lat, lon, deps: { fetch: typeof fetch })` → `{ tempC, code, maxC, minC, rainProb } | null` (timeout 5 s via `AbortSignal.timeout`, valida o JSON, arredonda); `reverseCity(lat, lon, deps)` → `string | null` (Nominatim: `address.city ?? town ?? village ?? municipality ?? county`, com cache por coordenada arredondada a 2 casas e `User-Agent`); `weatherText({ city, w })` em pt-BR conforme o spec ("1 grau"/"22 graus", "mínima de", chance de chuva só se ≥ 20 %, sem cidade quando `city` é null); `wmoDescription(code)`. Testes com `fetch` falso: texto completo, sem cidade, chance de chuva baixa omitida, temperatura negativa, resposta inválida/HTTP 500/timeout → `null`, cache de cidade (2ª chamada não usa a rede).

### Task B — Banco + ponte: integração (**depois** do agente "parar música" terminar)
Migração acima + pgTAP; `scheduler.ts` (`WakePlan` += `includeWeather`, `deviceActions`, `phoneAlarm`; `RunStatus` += `'skipped'`; `skipped` conta como execução final, nunca rearmada), `supabase-store.ts` (`toPlan`; `loadPresenceInput()` lendo `user_settings` e `user_locations`; `finishRun` aceita `'skipped'`), `wake.ts` (`fireWake`: avaliar presença **antes** de reivindicar efeitos: `away` → apagar o alarme reserva, `finishRun('skipped', …)`, nada mais; clima entra no texto via `buildBriefing(..., weather)`; ações de dispositivos em paralelo), `briefing.ts` (parâmetro opcional `weather: string | null` logo após a data), `main.ts` (montar entradas; `wakeTest` ignora presença, mas fala clima e executa dispositivos). Testes em `wake.test.ts`/`briefing.test.ts`.

### Task C — App: domínio, dados e telas — **depois** do agente "parar música (app)" terminar
`UserSettings` += `homeLat`, `homeLon`, `homeRadiusM`, `requireHome`; `SettingsRepository` += `setHome(lat, lon)`, `clearHome()`, `setRequireHome(bool)` (gravam só esses campos); `GeoPoint`/`distanceMeters` e `presenceStatus(...)` (mesma regra da ponte) em `lib/domain/home_presence.dart`; `WakePlan` += `includeWeather`, `deviceActions` (`WakeDeviceAction`), `phoneAlarm` (enum, sem UI ainda); repositórios de localização (`MemoryLocationRepository`, `SupabaseLocationRepository` sobre `user_locations`, upsert por usuário) ligados em `main.dart` e `test/helpers.dart`; **Ajustes → "Minha casa"** (definir/redefinir/remover, status "Em casa / Fora (a 2,3 km) / Sem localização recente", chave "Só tocar o despertar quando eu estiver em casa", aviso de bateria e de permissão "o tempo todo"; avisar se a precisão do GPS > 30 m); **tela do despertar**: chave "Falar o clima" e seção "Dispositivos no despertar" (lista de ações com dispositivo, ação Ligar/Desligar/Brilho %, atraso 0/1/5/10/15/30 min, remover; botão "Adicionar dispositivo" com os smart não ocultos). Testes de domínio, repositório e telas (com `LocationService` falso).

### Task D — Android: localização real e relatório em segundo plano — **depois** do agente "ícone" terminar
`GeolocatorLocationService` (permissões em duas etapas: foreground → "o tempo todo", fluxo com `permission_handler`; `currentFix` com `LocationAccuracy.best`); `AndroidManifest.xml`: `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `ACCESS_BACKGROUND_LOCATION`; relatório **em primeiro plano** (ao abrir/retomar o app e ao ligar "só em casa") via `LocationRepository.report`; **segundo plano** com a mesma infraestrutura do `workmanager` dos widgets (tarefa `location-report`, a cada 15 min, só se casa definida e `require_home` ligado e permissão "o tempo todo" concedida): fix de até 30 s, `upsert` direto em `user_locations` com a sessão do Supabase (sem sessão → não faz nada); `override` em `main.dart` do `locationServiceProvider` e `locationRepositoryProvider`. Build debug + verificação do manifesto mesclado. **Aparelho real necessário** para validar o GPS: relatório diz o que o usuário deve testar.

## Fase 2 (depois): alarme no celular
`phone_alarm` por despertar + tela "Alarmes do celular" + checagem 2 min após o horário (`android_alarm_manager_plus`) + toque local, conforme o design aprovado no chat. Spec/plano próprios quando a Fase 1 estiver entregue.

## Constraints (todas as tasks)

pt-BR; `export PATH="$HOME/development/flutter/bin:$PATH"`; app: `flutter analyze` limpo + `TZ=America/Sao_Paulo flutter test --exclude-tags integration`; bridge: `cd bridge && npx vitest run` + `npx tsc -p tsconfig.typecheck.json`; banco **local** apenas (`npx supabase migration up --local`, `npx supabase test db`; nunca `db reset`, nunca `--linked`); ninguém faz `git commit`/`stash`; ninguém toca a VM, a nuvem ou `mcp/`; só a Task D roda Gradle. Em todas, **todas as consultas da ponte filtram por `user_id`**, e nenhuma coordenada, token ou segredo vai para logs.
